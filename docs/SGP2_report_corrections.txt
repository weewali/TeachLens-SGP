3.1.4 Event Storage and Summary Module  -  REPLACE THE FIRST PARAGRAPH
=====================================================================

After the physical indicators are extracted, the system saves the observations in JSONL files, with one event per line. Each event records the video identifier, an anonymous track ID, the role assumed from the camera view (teacher, student or unknown), the indicator name, start time, end time, duration, value, confidence, and an evidence-coverage label (adequate, limited or unknown). When the recording's metadata provides a start time, each event also stores its real (wall-clock) start and end time. The saved events are then processed by a summary module that produces a JSON file containing the main results of the analyzed recording. These summaries include instructor visibility time, visible student counts, posture durations, movement levels and, where zones are configured, time spent in each zone. Time that could not be measured is reported as unknown rather than as zero.

3.1.6 System Integration and Scalability  -  REPLACE THE PARAGRAPH
STARTING "However, the current prototype..."
=====================================================================

However, the current prototype processes each camera's recording separately and does not yet combine the instructor and student views into one synchronized analysis. As a first step, each event can carry a real (wall-clock) time read from the recording's metadata. In tests with phone cameras filming a synchronized clock, the recorded start time was about 0.7 to 0.95 seconds after the first frame, so these real times are accurate to about one second. This is enough for coarse alignment of the two cameras, but not for frame-level synchronization. The scalability of the system across many classrooms and long recordings has also not been formally evaluated.

3.3.1 Dataset Availability and Quality  -  REPLACE THE SECOND PARAGRAPH
=====================================================================

To address this, we organized the dataset structure and prepared annotation guidelines to improve consistency. We also simplified the detection task by using a single person class instead of separate instructor and student classes, with roles taken from the camera view (Section 3.3.2). The current analysis pipeline uses the pre-trained YOLO26 pose model and does not yet use this dataset. The dataset still requires further review to ensure that the training and testing data are properly separated and reliable.


=====================================================================
3.3.3 Camera Movement and Visibility  -  REPLACE THE LAST PARAGRAPH
=====================================================================

TeachLens recordings are designed to use static cameras on tripods, so image positions correspond to fixed classroom positions and zone calibration can be applied. For the operated web videos used during development, which pan, zoom and cut between shots, we implemented an experimental camera-motion compensation step. It matches background features between sampled frames, with people masked out, and estimates the camera's shift and zoom so that movement is measured relative to the scene. A cut, a sudden zoom, or too few matching features starts a new shot instead of guessing. This compensation has not yet been validated, and zone calibration is intended for fixed camera views.
